# ADR-001: Append-only shared evidence

**Status:** Accepted for ClauseForge 0.1  
**Decision date:** 2026-11-20

## Context

Service-owned databases would fragment the proof boundary and make browser restart retrieval ambiguous.

## Decision

Persist canonical EvidenceRecord values as fsynced JSONL in a shared mounted directory. Every record carries the prior digest; readers rebuild and verify the chain before accepting a new write.

## Consequences

Writes are simple, inspectable, and restart-safe. Concurrent multi-writer deployment requires one writer or an external append coordinator. Corruption becomes a loud integrity error rather than a partial read.

## Verification and reciprocal mapping

The acceptance surface is: clauseforge-persistence, clauseforge-audit, service create/audit routes, durable-retrieval journey. The corresponding implementation and failure tests must cite ADR-001; if that path is removed, this decision is reopened rather than preserved as orphaned documentation.
